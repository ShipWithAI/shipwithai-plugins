# Design Spec: AI Workflow Gates in `shipwithai-starter`

**Date:** 2026-05-28
**Status:** Approved
**Author:** Claude Code (brainstorming session)

---

## Overview

Add a "Development Workflow" section to the CLAUDE.md generated by `shipwithai-starter`, along with an **incremental interview** mechanism so the plugin auto-detects new questions on update and only asks the missing ones without re-running the full interview.

**Problem 1:** The plugin generates good project context but no AI workflow instructions — Claude does not know what process to follow when working on a task (plan first? TDD? code review gate?).

**Problem 2:** When the plugin adds new features (new questions), existing projects have no way to receive the update without re-answering everything.

**Solution:**
- Workflow gates: add one checkbox question to Part 3, generate a "Development Workflow" section in CLAUDE.md.
- Schema versioning: `starter-context.json` tracks version, `init --update` only asks missing fields, `review` detects outdated schema.

**Core value:** Plugin update → `review` detects it → user runs `init --update` → answers only new questions → CLAUDE.md updated.

---

## Architecture

### Files changed

```
plugins/starter/
├── skills/
│   ├── init/SKILL.md           ← +1 question at end of Part 3 + new --update mode
│   ├── setup-memory/SKILL.md   ← +1 section template + generation logic
│   └── review/SKILL.md         ← +1 schema version check + 1 component check + 1 drift rule
```

No new files. No changes to the tier model.

### Data flow — normal init

```
init (Part 3 interview)
  → user selects workflow gates
  → saves: starter-context.json → conventions.workflow_gates[] + schema_version: "1.1"

setup-memory (generate CLAUDE.md)
  → reads conventions.workflow_gates[]
  → generates "Development Workflow" section with matching instructions
```

### Data flow — plugin update scenario

```
Plugin update: schema_version bumped 1.0 → 1.1 (adds workflow_gates)

review (existing project)
  → reads starter-context.json → schema_version: "1.0"
  → compares with current plugin schema: "1.1"
  → flags: "Plugin has new questions (v1.1). Run /shipwithai-starter:init --update"

init --update (incremental interview)
  → reads starter-context.json
  → iterates through all interview questions
  → skips questions that already have answers
  → asks ONLY null/absent fields: workflow_gates
  → updates starter-context.json + schema_version
  → invokes setup-memory (merge mode)
```

### starter-context.json schema change

Bump version and add one field:

```json
{
  "version": "1.1",
  "tier": "full",
  "stack": { "...": "unchanged" },
  "conventions": {
    "formatter": "prettier",
    "branch_strategy": "gitflow",
    "commit_format": "conventional",
    "coverage_target": "80%",
    "workflow_gates": ["plan-before-code", "tdd", "code-review"]
  }
}
```

`workflow_gates` values: `"plan-before-code"` | `"tdd"` | `"code-review"` | `"security-review"` | `"none"`

`"none"` is mutually exclusive — if selected, it overrides all other gates. The interview UI enforces this: selecting "None" deselects all other options.

Backward compatible: `workflow_gates` absent → section not generated, `review` flags schema as outdated.

## Section 1: `init/SKILL.md` changes

### 1a — New question in Part 3 (Conventions)

**Location:** End of Part 3, after the commit format question (all tiers).

```
"Which workflow gates should Claude follow when working on tasks?"
(Select all that apply — selecting None deselects all others)

→ [ ] Plan/design before coding
      Claude must create a plan or design doc before writing code for any task > 30 min
→ [ ] TDD — write tests first
      Claude writes failing tests before implementation
→ [ ] Code review gate
      Claude runs code-reviewer agent after every significant change
→ [ ] Security review for sensitive areas
      Claude runs security-reviewer before committing to sensitive areas
→ [ ] None — let Claude decide
```

### 1b — New `--update` mode

Triggered by: `init --update` or when `review` suggests it.

```
Step 1: Read .claude/starter-context.json
        → Not found: "No context found. Run /shipwithai-starter:init for full setup."
        → Found: continue

Step 2: Compare existing fields against current schema (v1.1)
        → Find all fields that are null or absent

Step 3: For each missing field, ask the corresponding interview question only
        → Same wording as the full interview
        → Skip all fields that already have answers

Step 4: Update starter-context.json
        → Merge new answers in
        → Set version to "1.1"

Step 5: Invoke setup-memory (merge mode)
        → Adds/updates only sections with new data
        → Existing sections preserved
```

Schema fields by version:
```
v1.0: stack, project, architecture, conventions (formatter/branch_strategy/commit_format/coverage_target),
      permissions, hooks_selected, mcp_selected, agents_selected, ssot
v1.1: + conventions.workflow_gates
```

**Standalone mode** (`setup-memory` called directly, no context file):
Ask the workflow gates question. User skips → do not generate section, do not leave placeholder.

## Section 2: `setup-memory/SKILL.md` changes

### CLAUDE.md template — new section

Insert after the "Key conventions" section:

```markdown
## Development workflow

**When working on any task, Claude must follow these gates:**

- [one bullet per gate selected]
```

### Gate → instruction mapping

| Gate | Instruction |
|---|---|
| `plan-before-code` | **Plan first:** For any task > 30 min, create a plan and get approval before writing code. |
| `tdd` | **TDD:** Write failing tests first. Never write implementation without a corresponding test. |
| `code-review` | **Code review:** Run the code-reviewer agent after every significant change. Address all CRITICAL and HIGH findings. |
| `security-review` (sensitive_areas present) | **Security review:** Before committing to `src/auth/, src/payments/` (from `architecture.sensitive_areas`), run security-reviewer agent. |
| `security-review` (sensitive_areas empty) | **Security review:** Before committing to sensitive areas (auth, payments, migrations), run security-reviewer agent. |
| `none` / empty | *(section omitted entirely)* |

### Example output (plan-before-code + tdd + code-review selected)

```markdown
## Development workflow

**When working on any task, Claude must follow these gates:**

- **Plan first:** For any task > 30 min, create a plan and get approval before writing code.
- **TDD:** Write failing tests first. Never write implementation without a corresponding test.
- **Code review:** Run the code-reviewer agent after every significant change. Address all CRITICAL and HIGH findings.
```

### Merge behavior

If CLAUDE.md already has a "Development workflow" section:
→ Offer Overwrite / Keep existing / Skip — consistent with behavior for all other sections.

## Section 3: `review/SKILL.md` changes

### Step 1 — Score Components (add 2 lines)

```
starter-context.json schema  → current (1.1) ✅ / outdated ⚠️ / missing ❌
CLAUDE.md workflow section   → present ✅ / opted-out ✅ / missing ⚠️
```

### Schema version check logic

```
Read .claude/starter-context.json:
  → not found                     → ❌ not initialized
  → version == "1.1"              → ✅ current
  → version < "1.1" or absent     → ⚠️ outdated (report current vs expected)
```

### Workflow section check (smart opt-out detection)

```
starter-context.json exists:
  → workflow_gates absent                → ⚠️ schema outdated — run init --update
  → workflow_gates == ["none"] or []     → ✅ explicitly opted out
  → workflow_gates has values            → check CLAUDE.md has "Development workflow" section
      present                            → ✅
      missing                            → ⚠️ context set but CLAUDE.md not updated

starter-context.json not found:
  → check CLAUDE.md for "## Development workflow" section
      present                            → ✅
      missing                            → ⚠️ no workflow section found
```

### Step 2 — Drift Detection (add 1 rule)

```
workflow_gates  ←→  architecture.sensitive_areas
  sensitive_areas present in starter-context.json
  AND "security-review" not in workflow_gates?
  → flag ⚠️ "Sensitive areas detected but no security-review gate configured"
```

### Health report table (add 2 rows)

```
| Schema version      | ⚠️ | v1.0 → v1.1 available (workflow_gates)          |
| CLAUDE.md workflow  | ⚠️ | Schema outdated — run init --update             |
```

### Suggest actions

Schema outdated:
> "Plugin has new questions (v1.1). Run `/shipwithai-starter:init --update` to answer only new questions — existing answers are preserved."

Workflow section missing (schema current):
> "Development workflow section missing from CLAUDE.md. Run `/shipwithai-starter:init --update` to add it."

---

## Tier

Workflow instructions belong to **Tier 1 (Essential)** — all tiers receive them.

Schema versioning applies to the entire plugin regardless of tier.

---

## Future-proofing

Each time the plugin adds a new feature:
1. Add the question to the interview (`init/SKILL.md`)
2. Add the field to the `starter-context.json` schema
3. Bump `schema_version`
4. `review` automatically detects outdated existing projects
5. `init --update` asks only the new field — does not re-ask answered questions

---

## Out of Scope

- Separate `add-workflow` command (superseded by `init --update`)
- Separate `setup-workflow` skill (overkill for the value delivered)
- Autonomous inference from team_size/stage (unreliable, lacks transparency)
- Enforcement mechanisms beyond CLAUDE.md instructions
